## 🚀 Deployment

### GitHub Pages (Recommended)

The site is built before it's served: `tsc` compiles the TypeScript to ES
modules in `dist/`, and `assemble-dist.js` adds `index.html`, `_headers`,
`css/`, and the event JSON. A GitHub Actions workflow
(`.github/workflows/pages.yml`) runs this build and uploads the finished
`dist/` to GitHub Pages on every push to `main`.

To enable it (one-time):
1. Push this repo to GitHub
2. Go to **Settings → Pages → Build and deployment → Source** and select **GitHub Actions**
3. Push to `main` — the workflow builds and deploys automatically
4. Your game will be live at:
   ```
   https://<your-username>.github.io/<repo-name>/
   ```

### Local Development

Vite provides a dev server with HMR — edit a file, see the change instantly:

```bash
npm install      # installs dev dependencies
npm run dev      # starts Vite dev server at http://localhost:8000
```

Open `http://localhost:8000` — that's it. No second terminal, no build step.

Vite transpiles TypeScript on the fly and serves `src/index.html` directly.
The `fetch()` calls for event JSON resolve against `src/data/` automatically.

> **Note:** HMR works best for CSS/HTML changes. JS module edits trigger a
> full page reload (the game's module-level state resets). For a full
> production build, use `npm run build && npm run assemble`.

## 🛠️ Tech Stack

- **HTML5 / CSS3 / TypeScript** — No frameworks; `tsc` compiles TS to ES modules in `dist/`
- **Vite** — Dev server with HMR (edit → instant, no refresh). Production build still uses `tsc`
- **TypeScript** — Full `strict` type checking + a build step (`tsc`) that emits plain JS
- **Web Audio API** — 8 synthesized SFX + looping BGM + victory/defeat jingles, no audio files
- **Navigator Vibration API** — haptic feedback on key moments (no-op on unsupported platforms)
- **Node VM test suite** — Core game logic tested against the built output, without a browser or framework
- **LocalStorage** — Save games and meta-progression
- **Single-Page Application** — Screen-based navigation
- **Mobile-First Responsive Design** — Works on all screen sizes

## 🧪 Building & Verifying

Two pipelines: **Vite** for development (HMR), **tsc** for production builds
and tests. The browser dev server and the test harness both load the source,
so you always verify what ships:

```bash
npm install          # installs dev dependencies (typescript, vite)
npm run dev          # Vite dev server with HMR at http://localhost:8000
npm run build        # one-off tsc build to dist/
npm run assemble     # rewrite Vite refs → prod refs, copy css/ + data/ to dist/
npm run typecheck    # type-check without emitting
npm test             # build + assemble, then run the core + smoke tests against dist/
```

- The source is TypeScript (`src/js/*.ts`) under full `strict` checking; [`src/js/core/types.ts`](src/js/core/types.ts) holds the shared types (interfaces — no runtime code).
- [`tsconfig.json`](tsconfig.json) is the type-checker config (`noEmit`); [`tsconfig.build.json`](tsconfig.build.json) extends it to emit to `dist/`.
- The emitted JS is **ES modules** (no bundler): `index.html` loads a single `<script type="module">` entry, and the rest of the graph arrives via static imports. In dev, Vite serves `/js/app.ts` directly; in production, `assemble-dist.js` rewrites it to `js/app.js?v=<version>`. Sub-resources are fetched by bare URL, so `src/_headers` asks GitHub Pages to revalidate `/js/*` and `/css/*`.
- The tier folders are the dependency layers: `core ← data ← engine ← ui ← app`. A test in [`test/core.test.js`](test/core.test.js) enforces the direction (core never imports data/engine/ui; data never imports ui; engine never imports ui; the only data→engine imports are the documented `special.js` reads).
- Tests live in [`test/`](test/): the runner stubs `localStorage`, then **imports the built modules** (`dist/js/`) as real ES modules, so the rules (stat checks, perk activation and grace rules, equipment drops, carry-over) are verified against exactly what ships. Tests control dice through the `Dice` facade (`Dice.d20 = () => 20`) and swap the event pool in place (`EVENTS.splice(...)`).
- A smoke test ([`test/smoke.test.js`](test/smoke.test.js)) verifies the built `dist/` is a self-contained, deployable site — every referenced asset, every relative import in the module graph, and every runtime-fetched event is present (checks the filesystem, no live server).
- CI (`.github/workflows/ci.yml`) runs `npm run typecheck`, `npm run build`, and `npm test` on every push to `main` and on all pull requests (Node 24, three jobs).
- Deployment (`.github/workflows/pages.yml`) builds the site and uploads `dist/` to GitHub Pages on every push to `main`.
